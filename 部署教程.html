赛博客服系统 Docker 部署教程

单容器部署 · 使用 deploy.sh 一键部署 · 四端口分离（9000 段）· PostgreSQL

前提条件

  • 服务器已安装 Docker 和 Docker Compose
  • 服务器开放端口 9000（访客聊天）、9001（管理后台）、9002（API）、9003（Widget）
  • 如需使用域名：宿主机已安装 Nginx 并配置好域名解析和 SSL 证书
! 如果服务器 80 端口已被宿主机 Nginx 占用，Docker 容器使用 9000/9001/9002/9003 端口，由宿主机 Nginx 反代到这些端口。

1首次部署

将部署包上传到服务器后，执行以下命令：

# 解压部署包
tar -xzf agenthub-docker.tar.gz
cd agenthub-docker

# 一键部署（自动生成 .env 配置文件）
bash deploy.sh

deploy.sh 会自动完成：

  • 生成 24 位高强度 PostgreSQL 密码
  • 创建 .env 配置文件（含端口、数据库名、密码）
  • 构建 Docker 镜像（首次约 3~5 分钟）
  • 启动容器并等待服务就绪
✓ 部署完成后，终端会显示 PostgreSQL 密码，请务必记录。密码也可在 .env 文件中查看。

2重新部署（更新版本）

当有新版本代码需要更新时，使用 redeploy.sh 一键重新部署：

# 上传新的部署包并解压
tar -xzf agenthub-docker.tar.gz
cd agenthub-docker

# 将旧 .env 复制过来（保留原有的数据库密码和配置）
cp ../agenthub-docker/.env . 2>/dev/null || true

# 一键重新部署
bash redeploy.sh

redeploy.sh 会自动完成：

  • 停止并删除旧容器
  • 使用 --no-cache 重新构建镜像
  • 启动新容器并等待服务就绪
i 重新部署前请确保 .env 文件存在且数据库密码与首次部署一致，否则数据将无法访问。

!彻底清除并重新部署

当遇到严重问题需要从零开始时，可以彻底删除所有容器、数据卷和镜像，然后全新部署。

!! 警告

此操作将永久删除所有数据，包括：

  • PostgreSQL 数据库中的全部数据（管理员、客服、会话记录等）
  • Redis 缓存数据
  • 上传的文件（图片、文档等）
  • Docker 命名卷中的所有持久化数据

此操作不可恢复！执行前请务必备份重要数据！

如仅需更新代码版本（保留数据），请使用上方的「重新部署」而非此方法。

确认已备份并需要彻底清除后，执行以下命令：

# 1. 进入部署目录
cd agenthub-docker

# 2. 停止并删除容器 + 所有数据卷
docker compose down -v

# 3. 删除旧镜像
docker rmi $(docker images -q agenthub-app 2>/dev/null) 2>/dev/null
docker image prune -f

# 4. 删除整个旧部署目录
cd ..
rm -rf agenthub-docker

# 5. 上传新的 agenthub-docker.tar.gz 并解压
tar -xzf agenthub-docker.tar.gz
cd agenthub-docker

# 6. 全新部署
bash deploy.sh
✓ docker compose down -v 中的 -v 参数会删除所有命名数据卷。部署完成后系统会以全新状态启动，deploy.sh 会生成新的数据库密码。

配置说明（.env 文件）

所有配置通过 .env 文件管理，不建议手动编辑 docker-compose.yml 或其他配置文件。

.env 文件由 deploy.sh 自动生成，内容如下：

# 项目名称
PROJECT_NAME=agenthub

# API DLL 文件名
APP_DLL_NAME=Sb.Apps.AgentHub.WebApi.dll

# 对外端口（四端口分离，9000 段）
CHAT_PORT=9000
ADMIN_PORT=9001
API_PORT=9002
WIDGET_PORT=9003

# PostgreSQL（密码已自动生成）
POSTGRES_DB=sb_agent_hub
POSTGRES_PASSWORD=AutoGenerated24CharPassword

# 数据持久化
# 留空 = Docker 命名卷（内置）
# 填路径 = 绑定挂载到宿主目录（外置）
#   POSTGRES_DATA_PATH=./data/postgresql
#   REDIS_DATA_PATH=./data/redis
#   UPLOAD_DATA_PATH=./data/upload
POSTGRES_DATA_PATH=
REDIS_DATA_PATH=
UPLOAD_DATA_PATH=

可调整的配置项

变量默认值说明
CHAT_PORT9000访客聊天端对外端口
ADMIN_PORT9001管理后台对外端口
API_PORT9002API 对外端口
WIDGET_PORT9003Widget 挂件对外端口
POSTGRES_DBsb_agent_hub数据库名称
POSTGRES_PASSWORD自动生成PostgreSQL postgres 用户密码（勿修改）
POSTGRES_DATA_PATH留空填路径则 PostgreSQL 数据外置到宿主目录
REDIS_DATA_PATH留空填路径则 Redis 数据外置到宿主目录
UPLOAD_DATA_PATH留空填路径则上传文件外置到宿主目录

端口与服务说明

端口服务容器内路径说明
9000 访客聊天端 /app/chat-ui 面向访客的聊天页面
9001 管理后台 /app/admin-ui 客服管理后台界面
9002 API 服务 /app/api .NET API 直通（SignalR + REST）
9003 Widget 挂件 /app/widget 可嵌入网站的客服挂件

容器内部还运行着 PostgreSQL（5432）和 Redis（6379），但不对外暴露端口，仅在容器内部通信。

域名与 SSL 配置（宿主机）

域名和 SSL 在宿主机 Nginx 层配置，容器不参与。以下为参考配置：

# 宿主机 /etc/nginx/conf.d/your-domain.conf

# 管理后台 — admin.yourdomain.com
server {
    listen 443 ssl;
    server_name admin.yourdomain.com;

    ssl_certificate     /path/to/cert.pem;
    ssl_certificate_key /path/to/key.pem;

    location / {
        proxy_pass http://127.0.0.1:9001;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_read_timeout 86400;
    }
}

# 访客聊天 — chat.yourdomain.com
server {
    listen 443 ssl;
    server_name chat.yourdomain.com;

    ssl_certificate     /path/to/cert.pem;
    ssl_certificate_key /path/to/key.pem;

    location / {
        proxy_pass http://127.0.0.1:9000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_read_timeout 86400;
    }
}

# Widget 挂件 — widget.yourdomain.com
server {
    listen 443 ssl;
    server_name widget.yourdomain.com;

    ssl_certificate     /path/to/cert.pem;
    ssl_certificate_key /path/to/key.pem;

    location / {
        proxy_pass http://127.0.0.1:9003;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_read_timeout 86400;
    }
}

# API — api.yourdomain.com
server {
    listen 443 ssl;
    server_name api.yourdomain.com;

    ssl_certificate     /path/to/cert.pem;
    ssl_certificate_key /path/to/key.pem;

    location / {
        proxy_pass http://127.0.0.1:9002;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_read_timeout 86400;
    }
}

# HTTP → HTTPS 重定向
server {
    listen 80;
    server_name chat.yourdomain.com admin.yourdomain.com api.yourdomain.com widget.yourdomain.com;
    return 301 https://$host$request_uri;
}

系统初始化

首次部署完成后，需要进行系统初始化：

1. 数据库迁移

API 启动后会自动执行数据库迁移（FreeSql），创建所有表结构和初始数据。

2. 创建管理员账号

访问管理后台 http://服务器IP:9001，根据提示创建超级管理员账号。

3. 配置客服系统

  • 登录管理后台后，在「系统设置」中配置基础参数
  • 创建客服账号和分组
  • 配置自动回复、满意度评价等功能
  • 在「平台管理」中创建接入平台，获取 Widget 嵌入代码

4. 部署 Widget 挂件

将 Widget 代码嵌入到你的网站中，访客点击即可发起咨询。Widget 资源由 9003 端口提供服务。

常用运维命令

# 查看容器状态
docker compose ps

# 查看实时日志
docker compose logs -f

# 只看 API 日志
docker compose logs -f app | grep api

# 重启容器
docker compose restart

# 停止容器
docker compose down

# 启动容器（不重新构建）
docker compose up -d

# 进入容器
docker compose exec app bash

# 查看容器内服务状态
docker compose exec app supervisorctl status

# 重启某个服务（如 api）
docker compose exec app supervisorctl restart api

# 查看 PostgreSQL 密码
grep POSTGRES_PASSWORD .env

# 连接 PostgreSQL
docker compose exec app psql -U postgres -d sb_agent_hub

常见问题

Q: 端口 9000/9001/9002/9003 被占用怎么办？

编辑 .env 文件修改对应端口号，然后运行 docker compose up -d 重启。

Q: 忘记数据库密码怎么办？

在部署目录运行 grep POSTGRES_PASSWORD .env 即可查看。密码在首次部署时由 deploy.sh 自动生成。

Q: 如何将数据外置到宿主机？

编辑 .env，设置：

POSTGRES_DATA_PATH=./data/postgresql
REDIS_DATA_PATH=./data/redis
UPLOAD_DATA_PATH=./data/upload

然后运行 docker compose up -d 重启容器。

Q: 重新部署后数据会丢失吗？

不会。只要 .env 中的 POSTGRES_PASSWORD 和 POSTGRES_DB 与首次部署一致，Docker 命名卷会保留数据。redeploy.sh 会自动复用 .env。

Q: WebSocket 连接失败怎么办？

检查宿主机 Nginx 配置是否正确设置了 proxy_http_version 1.1、proxy_set_header Upgrade 和 proxy_set_header Connection "upgrade"，以及 proxy_read_timeout 是否设置为足够大的值（建议 86400）。

Q: 上传文件大小有限制吗？

系统默认最大上传 10MB。如需调整，在管理后台「系统设置」中修改，同时确保宿主机 Nginx 的 client_max_body_size 也相应调整。
